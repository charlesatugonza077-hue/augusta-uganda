# Development workflow

## GitHub-first rule
Start each change here. The repository holds the working source, not just a copy of the finished website.

## Before changing anything
1. Pull or inspect the current `main` branch.
2. Create or update source files in their relevant folder.
3. Test links, mobile layout and form behaviour.
4. Commit a clear description of what changed.
5. Verify the GitHub Pages deployment after the commit.

## Change categories
- **Interface:** layout, copy, accessibility, navigation and responsive behaviour.
- **Design:** colours, type, components, imagery, interaction patterns and user journeys.
- **Front end:** HTML, CSS, JavaScript and browser behaviour.
- **Back end:** APIs, data storage, email or CRM integrations, authentication and validation.
- **Operations:** hosting, domains, deployments, search indexing and monitoring.

## Definition of done
A change is finished only when the repository contains the source and configuration needed to reproduce it, and the public deployment has been checked.
